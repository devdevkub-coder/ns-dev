# คู่มือใช้งานหมวดการผลิต

## ขอบเขต

คู่มือนี้อธิบายการใช้งาน 3 หน้าที่อยู่ในเมนู `การผลิต`:

| หน้า | Route | ใช้ทำอะไร |
|---|---|---|
| แดชบอร์ดการผลิต | `/production/dashboard` | ดูภาพรวม output, WIP, yield, loss และการใช้เครื่องจักร |
| ใบสั่งผลิต | `/production/orders` | สร้างใบผลิต, เบิกวัตถุดิบเข้า WIP, รับผลผลิต, คืนวัตถุดิบ และปิดงาน |
| รายงานการผลิต / Yield | `/production/report` | วิเคราะห์ผลผลิต ต้นทุน yield, loss และ WIP ตามช่วงวันที่ |

รายละเอียดเชิงธุรกิจและ API ให้ดูต่อที่ [Production Flow.md](Production%20Flow.md), [production-production-orders.md](page-flows/production-production-orders.md) และ [Production Order DB API Design.md](Production%20Order%20DB%20API%20Design.md)

## ลำดับการทำงานมาตรฐาน

### 1. สร้างใบสั่งผลิต

1. เปิดหน้า `ใบสั่งผลิต` แล้วกดสร้างรายการใหม่
2. เลือกสาขา สินค้าที่ต้องการผลิต เครื่องจักร และไลน์ผลิต
3. หากไม่มีเครื่องจักรหรือไลน์ผลิต ให้เลือก `ไม่มีเครื่องจักร` หรือ `ไม่มีไลน์ผลิต` ระบบจะบันทึกเป็น `null`
4. บันทึกใบสั่งผลิต ระบบยังไม่ตัด stock และสถานะเริ่มต้นเป็น `Open`
5. หลังบันทึก ระบบเปิดรายละเอียดใบสั่งผลิตรายการใหม่ให้ทำงานต่อทันที

### 2. เบิกวัตถุดิบเข้า WIP

1. เปิดแท็บ `วัตถุดิบที่เบิก`
2. ตรวจสอบ stock ที่เลือกได้ตามสาขาและคลังต้นทาง โดยไม่รวมคลัง WIP
3. เพิ่มวัตถุดิบได้หลายรายการ แต่ละรายการต้องระบุสินค้า คลังต้นทาง และน้ำหนัก
4. น้ำหนักต้องมากกว่า 0 และต้องไม่เกิน stock ที่มีอยู่
5. กดบันทึกการเบิก ระบบจะทำ input event ภายใน PO ใน transaction เดียว:
   - ตัด stock ออกจากคลังต้นทาง
   - เพิ่มสินค้าเดียวกันเข้า WIP
   - เก็บ WAC ของคลังต้นทาง ณ เวลาที่เบิกเป็นต้นทุน snapshot
6. วันที่และเวลาเบิกถูกสร้างจากเวลาบันทึกจริง ระบบไม่ให้เลือกวันที่ย้อนหลังจากช่องกรอก

สถานะหลังเบิกจะเป็น `In Production` และ WIP summary จะแสดงปริมาณ, มูลค่า และต้นทุนเฉลี่ย WIP แยกตามสินค้า/ประเภท/คลังต้นทาง

### 3. บันทึกผลผลิต

1. เปิดแท็บ `ผลผลิต`
2. ตรวจสอบตารางสรุปวัตถุดิบใน WIP ก่อนเลือกใช้ผลิต
3. เพิ่มรายการวัตถุดิบใน WIP ได้หลายรายการ และระบุน้ำหนักที่ใช้ต่อรายการ
4. จำนวนที่ใช้ผลิตต้องไม่เกิน `คงเหลือใน WIP`; ถ้าเกิน ระบบแสดงค่าติดลบและแจ้งว่าไม่เพียงพอ โดยไม่บันทึกจนกว่าจะแก้ไข
5. ตาราง `รายการผลผลิตที่ได้` รองรับผลผลิตหลายสินค้า และรองรับกรณีสูญเสียทั้งหมดโดยมีผลผลิตเป็น 0 สินค้าที่ได้จริงอาจต่างจากสินค้าเป้าหมายที่ระบุไว้ตอนสร้างใบสั่งผลิต จึงต้องเลือก actual output product ในแต่ละรายการ
6. ผลผลิตต้องเลือกคลังรับผลผลิตตามสาขาที่ผลิต และ loss ไม่ต้องเลือกคลังรับผลผลิต
7. ระบบเปรียบเทียบ `ผลผลิตรวม + loss` กับน้ำหนัก WIP ที่ใช้ หากไม่เท่ากันจะแจ้งเตือนให้ยืนยันก่อนบันทึก ความแตกต่างนี้เกิดขึ้นได้ตามกระบวนการผลิตและไม่ถือเป็นข้อผิดพลาดโดยตัวมันเอง โดยเฉพาะกรณีมี loss
8. เมื่อบันทึก ระบบสร้าง output event/round ภายใน PO และมีผลต่อ stock/WIP ทันที:
   - ตัด WIP ตาม source WIP ที่เลือก
   - รับ FG/RM เข้าคลังปลายทางด้วย WAC ปัจจุบันของคลังปลายทาง
   - บันทึกต้นทุนการผลิตจาก WIP แยกจากต้นทุนรับเข้าคลัง
   - บันทึกผลผลิตและ loss ในประวัติใบสั่งผลิต

ผลผลิตแต่ละรอบเป็น movement ใหม่ หากต้องแก้จำนวนที่รับเข้าคลังแล้ว ให้ใช้ void รายการเดิมแล้วสร้างรายการใหม่ หรือเพิ่มรอบใหม่เมื่อเป็นการผลิตเพิ่มจริง ห้ามแก้ ledger เดิมโดยตรง

### 4. คืนวัตถุดิบจาก WIP

1. เปิดแท็บ `วัตถุดิบที่เบิก` แล้วกด `คืนวัตถุดิบ`
2. ระบบรวมรายการที่อยู่ใน WIP pool เดียวกันตามสินค้า ประเภท และคลังต้นทาง
3. หน้าคืนแสดง WIP WAC ปัจจุบัน ไม่พยายามระบุว่าคืนจากรอบเบิกใด เพราะของถูกรวมเป็น pool แล้ว
4. ระบุจำนวนคืนและเหตุผล โดยจำนวนคืนต้องไม่เกิน WIP ที่เหลือ
5. ระบบสร้าง return event ภายใน PO แบบ append-only:
   - ตัด WIP ออกด้วย WAC ปัจจุบันของ WIP
   - เพิ่มกลับคลังต้นทาง
   - คำนวณ WAC ของคลังปลายทางใหม่จากยอดเดิมกับยอดคืน
6. รายการเบิกเดิมยังคงแสดงในประวัติ ส่วนยอดคืนอยู่ในรายละเอียด timeline และตารางคืน

การคืนไม่ใช่เอกสารเบิกเข้า WIP และไม่ใช่การรับซื้อเข้า stock: เป็น event การคืนของจาก WIP โดยมี ledger คู่คือ `PRODUCTION_INPUT_RETURN_WIP_OUT` (ออกจาก WIP) และ `PRODUCTION_INPUT_RETURN_STOCK_IN` (เข้าคลังต้นทาง)

การคืนไม่ลบ ledger เดิม และไม่สร้างเอกสาร reverse ปลอมสำหรับการคืนวัตถุดิบ

### 5. จบงานผลิต

1. กด `จบงาน` จากรายละเอียดหรือเมนูจัดการของใบสั่งผลิต
2. ถ้า WIP เหลือ ระบบจะแสดงจำนวนที่เหลือและขอการยืนยัน
3. เมื่อยืนยัน ระบบคืน WIP ที่เหลือกลับคลังต้นทางด้วย return event ภายใน PO ใน transaction เดียว
4. เมื่อคืนสำเร็จครบแล้ว สถานะจะเปลี่ยนเป็น `Completed`
5. ถ้าไม่ยืนยัน ระบบจะไม่ปิดงานและไม่สร้าง movement เพิ่ม

## สถานะใบสั่งผลิต

| สถานะ | เกิดเมื่อ | ความหมาย |
|---|---|---|
| `Open` | สร้างใบสั่งผลิตสำเร็จ | ยังไม่มีการเบิกเข้า WIP |
| `In Production` | มีการเบิกเข้า WIP | มี WIP พร้อมใช้ผลิต |
| `Partially Completed` | มีผลผลิตแล้วแต่ยังมี WIP | ยังเพิ่มผลผลิตหรือคืน WIP ได้ |
| `Completed` | ผู้ใช้จบงานและ WIP ถูกใช้หมดหรือคืนครบ | ปิดงานแล้ว |
| `Cancelled` | ยกเลิกและชดเชย movement ครบ | ไม่สามารถทำรายการต่อ |

## การยกเลิกและ Void

- `ยกเลิกใบสั่งผลิต` จะชดเชยผลผลิตที่ยัง active กลับ WIP และคืนวัตถุดิบ WIP ที่เหลือกลับคลังต้นทางใน transaction เดียว
- ใบที่ `Completed` ยกเลิกได้เฉพาะภายใน grace period 7 วัน และต้องไม่มี downstream transaction ที่ทำให้การชดเชยไม่ปลอดภัย
- `Void ผลผลิต` ใช้กับผลผลิตแต่ละรอบที่รับเข้าคลังแล้ว ระบบจะตรวจว่าผลผลิตนั้นถูกนำไปใช้ต่อหรือไม่ก่อนยกเลิก
- ไม่มีเมนูหรือ API สำหรับ `reverse`; การแก้ไขใช้คำสั่งคืนวัตถุดิบหรือยกเลิกผลผลิต และเก็บ timeline เพื่อ audit โดยไม่แก้หรือลบ ledger เดิม

## ตรวจสอบเมื่อข้อมูลไม่ตรง

1. ตรวจ WIP summary เทียบกับ PO input/return events
2. ตรวจผลผลิตเทียบกับ PO output/void events
3. ตรวจ stock ledger ของคลังต้นทาง คลัง WIP และคลังรับผลผลิตตาม document reference
4. ตรวจ timeline ว่ามีผู้ดำเนินการ เวลา เหตุผล และรายละเอียด source WIP ครบหรือไม่
5. หากพบข้อมูล ledger ไม่สมดุล ให้หยุดการแก้ด้วยการปรับยอดมือ และใช้ reconciliation/API หรือ migration ที่มี audit แทน

## Active Numbering Rule 2026-07-28

ผู้ใช้เห็นเลขเอกสารการผลิตเป็นเลข `PO` ที่มีรหัสสาขาเท่านั้น. การเบิกวัตถุดิบและการรับผลผลิตเป็น event ภายใน PO; รอบรับผลผลิตแสดงเป็น `PO.../01`, `/02`. คำว่า `PI`/`PO2` ที่ปรากฏใน technical ledger classification ไม่ใช่เลขเอกสารที่ผู้ใช้ต้องกรอกหรือค้นหา. การคืน/ยกเลิกอ้าง event เดิมและไม่สร้างเลข reversal ใหม่. ระบบใหม่ไม่ fallback หรือ backfill ข้อมูลเก่า.
